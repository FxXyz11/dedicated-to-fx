# Dedicated to Fx — 产品需求文档

> 文档状态：第一阶段产品定义  
> 版本：0.1  
> 目标平台：移动端优先的本地优先 PWA  
> 产品所有者：Fx

## 1. 产品摘要

Dedicated to Fx 是一套以英文文章为入口的个人阅读学习系统。它不把学习拆成孤立的“英文单词—中文释义”，而是让用户在真实文章中发现表达、根据上下文提出猜测、逐层获得提示、理解当前语境，再把这一理解连接到更稳定的核心语义概念和新的语境中。

产品希望促成的长期变化是：

> 从“看到英文 → 翻译成中文 → 理解”，逐渐转变为“看到英文 → 感知语境与表达意图 → 直接理解”。

它应当更像一册持续生长的数字英语手稿，而不是词典、题库或商业化学习平台。

## 2. 核心价值

### 2.1 对用户的价值

1. **保留完整阅读体验**：学习发生在文章内部，用户不会被生词列表夺走注意力。
2. **训练推断能力**：答案不会在点击后立即出现，用户先观察语境并形成自己的判断。
3. **建立语义网络**：同一个词在不同语境中的用法通过核心概念相连，而不是被记成多个互不相关的中文义项。
4. **积累个人证据**：系统保存“我在哪里遇到它、当时如何理解、犯过什么错、后来能否迁移”的长期记录。
5. **保持数据自主**：无需账号或云端，学习数据只保存在本机，并可导出备份。

### 2.2 产品差异

| 常见产品模式 | Dedicated to Fx |
| --- | --- |
| 从词表开始 | 从完整文章开始 |
| 点击即显示中文 | 猜测后逐层提示 |
| 一个词对应若干中文义项 | 当前语境与核心概念分层 |
| 记忆次数代表掌握 | 语境理解与迁移表现代表掌握 |
| 尽量标出所有生词 | 维持干净、连续的阅读 |
| 平台拥有学习数据 | 用户在本地拥有并可导出 |

## 3. 目标用户与核心问题

### 3.1 目标用户

- 中国大学生，主要使用手机阅读。
- 能在文章中定位信息，但对词汇和表达的细微变化把握不足。
- 容易依赖逐词翻译，希望逐渐形成英文理解路径。
- 对国画、插画、艺术设计、角色创作、中国传统文化、自然与动物有稳定兴趣。
- 同时需要接触大学英语四级常见主题与文体。

### 3.2 Jobs to Be Done

当我阅读一篇感兴趣或需要理解的英文文章时，我希望在不打断整体阅读的前提下探索真正影响理解的表达，并通过上下文和适度提示形成自己的判断；之后，我希望把这次理解连接到其他语境，并在未来再次遇到时更快、更直接地理解它。

### 3.3 关键痛点

- 知道一个词的常见中文义项，却无法解释它在当前句子中的作用。
- 一个词出现新用法时，误以为需要记忆一个全新的中文意思。
- 查词过程离开文章太久，导致篇章逻辑和阅读兴趣中断。
- 学习记录只有“收藏/未收藏”，没有保留理解过程和错误。
- 复习以识别中文翻译为主，不能证明能在新语境中理解。

## 4. 产品原则

以下原则按优先级排序，冲突时上位原则优先。

1. **文章优先**：所有词语学习必须从文章中的真实遇见开始，不能把词表设为默认入口。
2. **阅读优先**：只有影响理解或用户主动选择的表达才进入探索；正文默认不铺满标记。
3. **思考先于答案**：点击表达后先邀请猜测，再逐层提供线索。
4. **当前语境先于抽象总结**：先弄清作者此处在表达什么，再给核心概念。
5. **核心概念连接多义**：核心概念是教学模型，不是词典释义的改写，也不是强行用一句中文覆盖所有用法。
6. **英文解释优先，中文用于校准**：中文是必要的辅助脚手架，不是最终记忆目标。
7. **重新阅读闭环**：探索结束后必须自然返回原文，并鼓励重新读句子或段落。
8. **掌握需要证据**：不能因查看答案、收藏或一次答对而标记“已掌握”。
9. **本地优先与可迁移**：无登录、无服务器，数据可读、可导出、可恢复。
10. **克制胜过刺激**：不以排行榜、金币、连胜焦虑或高频提醒驱动学习。
11. **访问边界诚实**：线上入口提供首次访问密码门，阻止普通访客直接进入；不得将纯前端密码门描述为服务器级保密。

## 5. 产品目标与非目标

### 5.1 MVP 目标

- 在手机上完成“选择文章—连续阅读—探索表达—回到原文—记录学习”的完整闭环。
- 支持渐进式提示，不在第一步泄露答案。
- 清晰区分词条的核心概念与每一次遇见的具体语境。
- 离线阅读已缓存的文章，并在本地持久化学习记录。
- 为内置与本地导入文章提供开放许可的基础学习词典、词形还原、音标与系统英式/美式发音，同时保持答案后置。
- 能导出和恢复个人数据。
- 为后续复习与语义网络演进保留可靠的数据结构。
- GitHub Pages 线上入口在当前浏览器首次访问时要求密码，验证后记住本机授权；换设备、清除站点数据或更换密码后重新验证。

### 5.2 非目标

- 不做中英双栏自动翻译。
- 不把产品变成权威词典替代品，也不承诺覆盖姓名、拼写错误和全部专业术语；基础词典只提供一般词义可能性。
- 不做考试题库、排名、社交、打卡或付费体系。
- 不做账户、云同步、服务器端数据库。
- 不承诺纯静态密码门能够抵御查看源码、直接请求静态资源或修改浏览器状态的技术性绕过。
- 不调用需要在客户端保存密钥的第三方 AI/API。
- MVP 不自动生成核心概念；核心学习内容应由可信的人工策划内容提供。
- MVP 支持受控的纯英文文本导入，但不追求 PDF、网页抓取、复杂排版或任意文档解析。
- 不在无语言模型的情况下假装把中文自动改写为自然英文。

## 6. MVP 范围

### 6.1 Dashboard 首页

**目标**：让用户在十秒内知道今天可以读什么、最近学到了什么，并继续上次的学习。

**包含**

- 今日阅读任务：一篇推荐文章或继续未读文章。
- 当前阅读进度：文章、段落位置、预计剩余时间。
- 最近学习文章：最近三至五篇。
- 最近探索的表达：显示原语境摘要和当前理解状态，不显示孤立中文词义。
- 最近形成稳定理解的表达：仅展示已有概念连接或迁移证据的项目；没有可靠证据时隐藏该模块，不用一次查看冒充“掌握”。
- 学习统计：阅读天数、完成文章数、主动探索数、迁移练习数。

**约束**

- 统计用于回顾，不做竞争性排名或惩罚性连续打卡。
- 首页主行动始终是“继续阅读”或“开始阅读”，而不是“背单词”。

### 6.2 阅读页

**目标**：提供安静、连续、适合手机的英文阅读体验。

**包含**

- 文章标题、主题、难度、预计时长、正文与段落进度。
- 点击单词打开轻量探索入口；支持将相邻词扩展为短语或搭配。
- 点击后的轻面板可播放系统英式/美式发音；音标和词典释义不改变“先猜测、后解释”的顺序。
- 用户主动探索过的表达可使用极克制的二次标记。
- 保存阅读位置、完成状态和最后阅读时间。
- 探索结束后返回同一段落、同一滚动位置。

**不包含**

- 默认高亮系统判断的所有生词。
- 逐句中文翻译。
- 自动打断阅读的测验弹窗。

**本地文章导入**

- Fx 可以粘贴纯英文标题与正文，填写主题、难度和来源后保存到 IndexedDB。
- 导入内容按空行转换为受控段落块，不执行 HTML，单篇限制字符数并检查主要语言。
- 导入文章进入文章库、离线阅读、进度记录、每日推荐和完整数据备份。
- 任意导入文章中的普通单词可在猜测后查看开放许可基础词典的英文释义、中文辅助、词形和发音。
- 基础词典列出一般意义，不能自动判断当前句义；只有命中策划 LearningUnit 的表达才提供当前语境解释、核心概念连接与迁移练习。
- 中文内容提供“复制英文改写要求”的辅助流程，但站内不自动翻译或调用远程 AI。

### 6.3 单词/表达探索页

**目标**：用渐进提示帮助用户形成推断，并把当前理解连接到核心概念。

**固定顺序**

1. 原句与猜测输入。
2. Context clues：上下文中哪些信息限制了含义。
3. Part of speech & collocations：词性、句法角色和搭配。
4. Simple English meaning：简单英文解释。
5. Contextual meaning：当前语境理解；英文为主，中文辅助校准。
6. Core concept：跨语境的教学性核心概念。
7. Related contexts：其他语境及其与核心概念的连接说明。
8. Transfer practice：新语境判断、改写或造句。

**交互约束**

- 后续层级默认折叠，用户主动展开。
- 系统记录展开深度，但不将“少看提示”包装为优越感。
- 用户可以暂时离开并稍后继续，草稿不会丢失。
- 完成后首要行动是“回到原文再读一次”。

### 6.4 学习记录

**包含**

- 阅读过的文章和阅读位置。
- 探索过的词或多词表达。
- 每一次遇见的原句、段落和当前语境理解。
- 用户猜测、错误类型、提示使用深度和自评。
- 用户造句、迁移练习结果和复习时间。
- 核心概念理解随多次遇见逐步更新的记录。

**展示原则**

- 默认按文章和时间组织，保留“从哪里学到”的线索。
- 可以从一个表达查看多个语境，但不将词表变成主要学习入口。

### 6.5 私人日记与计划

- Journal 是专门写日记的空间，日记以本地日期为主键，保留创建与修改时间。
- 月历明确标出已经写过日记的日期；颜色之外同时提供完成标记和辅助技术文本。
- 英语学习轨迹迁移到独立二级页面，不与私人日记混在同一时间线中。
- Plans 分为“每日习惯”和“计划”两部分：前者按日期记录重复行动，后者保存有明确状态和可选目标日期的事项。
- 不引入连胜、惩罚、排名或其他制造压力的游戏化反馈。
- 日记、习惯和计划均只保存在 IndexedDB，并纳入 JSON 备份与恢复。

### 6.6 数据管理

- 导出完整 JSON 备份，包含 schemaVersion、导出时间和全部用户数据。
- 从 JSON 导入前进行版本和结构校验。
- 恢复前说明覆盖/合并策略，并提供二次确认。
- 设置页提示 iOS 可能清理长期未使用站点数据，建议定期备份。

## 7. 内容策略

### 7.1 MVP 内容来源

- 随应用内置少量经过策划、可合法使用的文章。
- 优先使用公版文本、自有内容、明确许可内容或为本产品原创的短文。
- 每篇文章附来源、作者、许可信息和内容版本。
- 已下载文章进入本地缓存，离线可读。

### 7.2 选题组合

- 兴趣主题：艺术、绘画、设计、人物、传统文化、自然、动物。
- 能力主题：科技、社会、校园与四级常见说明/议论文体。
- 难度应略高于舒适区，但不能依赖高密度查词才能理解主旨。

### 7.3 教学内容质量

每个预策划表达至少需要：

- 当前原句和充分上下文。
- 语境限定线索。
- 词性、句法角色与常见搭配。
- 简单英文解释。
- 当前语境的英文理解与中文辅助说明。
- 可迁移但不过度抽象的核心概念。
- 至少两个差异明显的相关语境。
- 每个语境如何从核心概念延伸的说明。
- 一个可验证的迁移练习与反馈依据。

当前首批扩充内容为 8 篇内置原创文章、16 个核心概念和 16 个完整渐进学习单元。新增文章以博物馆、植物园、开放获取论文和 NASA 等可靠资料为事实依据，正文重新撰写，并保留可访问的来源链接。

## 8. 关键用户故事与验收标准

### US-01 开始或继续阅读

作为 Fx，我希望打开网站后快速继续上次的文章，从而避免重新寻找阅读位置。

**验收**

- Dashboard 第一屏显示明确的继续阅读行动。
- 点击后恢复到上次段落附近。
- 离线且文章已缓存时仍可打开。

### US-02 主动探索表达

作为 Fx，我希望点击不理解的表达但不立即看到答案，从而先训练自己的推断。

**验收**

- 首屏仅显示原句、必要上下文和猜测输入。
- 答案性信息必须经主动操作逐层展开。
- 猜测即使为空也可继续，但系统温和邀请用户先写下判断。

### US-03 理解多义联系

作为 Fx，我希望看到当前含义与核心概念的联系，从而不把每个中文义项当成独立单词。

**验收**

- 当前语境含义和核心概念在界面与数据层是不同字段。
- 每个相关语境都有“如何连接核心概念”的说明。
- 中文辅助不能以“word = 中文”的形式作为标题或主记忆项。

### US-04 返回原文

作为 Fx，我希望探索结束后回到原来的位置重读，从而把新理解放回文章。

**验收**

- 返回后滚动位置和段落上下文不丢失。
- 目标句有短暂、低干扰的定位效果。
- 系统记录一次重读行动，而不是直接判定掌握。

### US-05 备份学习记录

作为 Fx，我希望导出本地数据，从而在更换设备或浏览器数据被清理时恢复。

**验收**

- 导出文件包含版本、时间和数据校验所需元信息。
- 导入损坏或不兼容文件时不修改现有数据。
- 用户明确确认后才执行覆盖或合并。

## 9. 成功指标

MVP 不追求日活或时长最大化，关注学习闭环是否发生。

### 产品健康指标

- 文章开始后到达结尾的比例。
- 探索后返回原文的比例。
- 用户在看到中文辅助前完成猜测的比例。
- 单次探索的中断率和平均停留时长。
- 本地写入、离线打开和数据恢复成功率。

### 学习信号

- 新语境中正确解释表达作用的比例。
- 同一表达再次遇见时所需提示层级是否下降。
- 用户能否说明当前用法与核心概念的连接。
- 用户造句是否保留目标表达的语义与搭配约束。

这些指标仅在本地计算并呈现给用户；MVP 不上传分析数据。

## 10. 风险、问题与缓解策略

| 风险/问题 | 影响 | MVP 缓解 |
| --- | --- | --- |
| 核心概念被写成模糊的“万能释义” | 产生错误迁移 | 建立内容撰写规范；允许一个词存在多个相关概念分支，不强行合并 |
| 单词点击忽略短语、固定搭配和语法结构 | 用户得到错误分析单位 | 点击后允许扩展选择范围；数据模型使用 expression 而非仅 word |
| 过多探索打断篇章理解 | 产品退化为查词器 | 不自动标生词；提示“先读完段落再探索”；保留阅读位置 |
| 渐进提示步骤过多、操作疲劳 | 用户跳过或放弃 | 前四层使用轻量底部面板；允许继续阅读后补完；根据内容省略不适用层但不越级泄露 |
| 英文解释太难，中文解释又形成依赖 | 脚手架失衡 | 英文解释限制词汇难度；中文只在后段出现；记录用户在哪层获得理解 |
| “掌握”定义过早 | 形成虚假进步感 | 采用多维状态；至少需要延迟后的新语境证据 |
| 文章或例句版权不清 | 无法安全发布 | 只使用原创、公版或明确许可内容，保存归属与许可元数据 |
| 自动分词对标点、词形和短语处理错误 | 点击体验不稳定 | 首版使用保守 tokenization，并允许用户手动调整表达范围 |
| IndexedDB 数据被系统/浏览器清理 | 长期记录丢失 | 明确备份提醒、导出/导入、数据健康检查；后续考虑文件系统导出 |
| PWA 在 iOS 的安装和缓存行为受限制 | 安装/离线体验不一致 | 提供 Safari“添加到主屏幕”指引；真机测试；离线状态清楚可见 |
| GitHub Pages 子路径和前端路由冲突 | 刷新页面 404 或资源失效 | 构建时配置 base；优先使用兼容静态托管的路由策略 |
| 无后端意味着跨设备无法自动同步 | 换机成本高 | 明确定位为本地优先；MVP 提供文件备份，不承诺云同步 |
| 内容制作成本高 | 功能完成但缺少高质量文章 | 先做少量“黄金样本”，验证学习流程后再扩充内容 |
| 用户兴趣内容与四级能力训练脱节 | 有趣但迁移不足 | 文章库同时标注主题、文体与能力目标，保持混合选材 |

## 11. 非功能需求

### 性能

- 移动端首屏应轻量，文章正文不依赖网络 API。
- 点击表达后的界面反馈应立即出现。
- 长文章渲染避免为每个词创建昂贵的全局状态订阅。

### 可访问性

- 正文、按钮和提示满足基本对比度与可缩放要求。
- 正文默认字号和行高适合连续阅读，最小触控目标约 44×44 CSS px。
- 所有层级展开可通过键盘操作，并有正确的焦点管理与屏幕阅读器标签。
- 不只使用颜色表达掌握状态。

### 隐私与安全

- 不采集账号、邮箱或设备身份。
- 不含分析 SDK、广告 SDK 或远程追踪。
- 不在前端代码、IndexedDB、构建变量中保存 API Key。
- 导入文件必须视为不可信输入，校验结构后再写入。

### 可靠性

- 数据库升级使用显式版本迁移，禁止无提示破坏旧数据。
- 核心学习写入操作具备事务边界。
- Service Worker 更新不能导致文章内容版本与学习记录失配。

## 12. 设计方向

### 气质

安静、克制、个人化、有纸张和墨迹的触感，但不做拟物化堆叠。

### 视觉语言

- 暖纸色背景、接近墨色的正文、低饱和植物或矿物色作为少量强调。
- 留白和排版承担层级，不依赖卡片墙与高饱和色块。
- 正文字体优先考虑长文可读性；标题可带适度人文气息。
- 动效短而轻，服务于位置保持、层级展开和返回原文。

### 应避免

- 儿童化插画、奖杯、金币、火焰连胜。
- 大面积渐变、高饱和按钮和商业课程宣传布局。
- 过密的数据看板和“效率焦虑”语言。
- 用装饰性水墨元素压过英文正文的可读性。

## 13. 待验证假设

1. 用户愿意在看到解释前先写一个很短的猜测。
2. 八层提示可以被组织得足够轻，不会让每次探索显得漫长。
3. 核心概念加连接说明比多义项列表更能帮助用户处理新语境。
4. “探索后返回重读”能明显改善对原段落的理解感。
5. 少量高质量策划文章足以验证产品价值，而不是先追求大内容库。
6. 文件导出/导入能满足 MVP 的数据迁移需要。

这些假设应在可用原型和首批文章上逐一验证，不应通过增加功能来回避。
