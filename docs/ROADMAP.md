# Dedicated to Fx — 产品与开发路线图

> 原则：先验证最小学习闭环，再扩内容与算法。路线图中的“完成”以可观察验收标准为准，不以文件数量或页面数量为准。

## 实施状态（2026-08-03）

- Milestone 1–4 的首个纵向版本已经实现：工程基础、阅读、渐进探索、学习轨迹、本地备份与 PWA。
- 个人空间已增加按日期书写的 Journal，以及分为每日习惯与计划的 Plans；两者纳入本地备份。
- 文章库已增加纯英文文本本地导入、My Imports 筛选和按本地日期轮换的每日推荐。
- 当前内置 8 篇原创学习文章，共含 16 个核心概念与 16 个完整渐进学习单元。
- 新增内容覆盖中国手卷、竹子、夜间昆虫、绘画保护与卫星森林观测，并保留事实参考来源。
- Milestone 5 仍需继续：目标用户可用性测试、iPhone Safari/主屏幕真机验证、更多策划文章与内容复核。
- GitHub Pages 首次访问密码门已完成本地实现与移动端验证，等待配置正式密码后发布。
- 第一版不包含账号登录、云同步、自动翻译、远程 AI 或追踪。

## 1. 当前阶段

### Phase 0 — 产品定义（本次交付）

**目标**

- 固化产品定位与不可违反的学习原则。
- 定义 MVP 边界、学习模型、数据模型和核心 UX。
- 建立后续开发目录骨架与协作规则。

**交付**

- docs/PRD.md
- docs/LEARNING_MODEL.md
- docs/DATA_MODEL.md
- docs/UX_FLOW.md
- docs/ROADMAP.md
- AGENTS.md
- 空的工程目录骨架

**退出条件**

- 产品、学习、数据和 UX 文档使用一致术语。
- 用户确认第一阶段方案。
- 在用户明确确认前，不初始化应用依赖，不实现页面或数据库代码。

## 2. MVP 优先级

### Must have

- 移动端优先的 Dashboard、Library、Reader、Exploration、Journal、Plans、Learning history、Settings。
- 至少一篇高质量“黄金样本”文章贯通完整流程。
- 单词和短语选择，预策划表达匹配。
- 八层渐进提示与返回原文重读。
- 阅读位置、Encounter、猜测、提示层级、练习和学习摘要的本地持久化。
- 私人日记、每日习惯与计划的本地持久化和日期状态展示。
- IndexedDB/Dexie schema 和可测试迁移。
- JSON 导出与可靠的替换恢复。
- 本地导入文章进入完整备份；任意导入内容不自动伪造翻译或教学讲解。
- PWA 安装基础、GitHub Pages 部署和已下载文章离线阅读。
- 首次访问密码门：验证后记住当前浏览器，换密码后旧授权自动失效；界面明确说明静态保护边界。
- iPhone Safari/主屏幕模式的真机验证。
- 基础可访问性、错误状态与本地数据风险提示。

### Should have

- 3–5 篇主题不同的策划文章。
- 表达历史的跨语境视图。
- 透明的规则型复习调度。
- 阅读字号、行高、减少动效等偏好。
- 文章内容包版本与重新下载。
- 安全合并备份；若首版成本过高则延后。

### Could have

- 用户导入纯文本/Markdown 文章。
- 本地内容编辑工具。
- 更丰富的文章内批注。
- 基于历史错误的提示排序。
- 文件系统直接保存备份。

### Won’t have in MVP

- 账号登录、云同步、后端数据库。
- 客户端暴露 API Key 的 AI 功能。
- 自动翻译整篇文章。
- 大而全的词典。
- 社交、排名、打卡连胜、金币或成就系统。
- PDF/网页抓取和任意复杂文档解析。
- 自动声称能准确评分所有自由造句。

## 3. 实施里程碑

### Milestone 1 — 工程基础与设计基线

**目标**

建立可部署、可安装、可测试的最小外壳，但不追求功能页面完整。

**工作**

- 初始化 React + TypeScript + Vite。
- 开启 TypeScript strict 和基础 lint/format/test。
- 建立 design tokens、全局排版与响应式容器。
- 配置 GitHub Pages base 路径和静态托管兼容路由。
- 配置 manifest、图标、Service Worker 基础。
- 建立 Dexie 数据库壳、schema version 1 和 repository 层。
- 制作真实纸色/墨色主题的最小视觉样张。

**验收**

- 本地与生产构建均通过。
- GitHub Pages 子路径可直接进入应用并刷新。
- 可在支持环境安装 PWA。
- 离线能打开应用外壳。
- DB 初始化失败有可见错误，不静默清库。
- 基础页面通过键盘和屏幕尺寸检查。

**需要先验证的技术风险**

- GitHub Pages 路由与 Vite base。
- iOS standalone 模式的导航恢复。
- Service Worker 更新与内容版本的一致性。

### Milestone 2 — 阅读纵向切片

**目标**

用一篇黄金样本完成“Today → Reader → 保存位置 → 完成文章”。

**工作**

- 创建 Dashboard 的今日任务和继续阅读。
- 创建 Library 与文章详情。
- 建立 Article/ArticleBlock 内容格式。
- 实现 Reader 排版、段落锚点和进度持久化。
- 实现离线文章安装状态。
- 准备第一篇合法来源或原创的黄金样本文章。

**验收**

- 手机上的首次开始与继续阅读都不超过两次主操作。
- 刷新、关闭再打开后恢复到正确段落。
- 更改字号后仍以稳定段落恢复。
- 已下载文章在飞行模式下可读。
- 正文没有自动铺满生词标记。

### Milestone 3 — 渐进探索纵向切片

**目标**

围绕黄金样本中的 5–8 个表达完成学习闭环。

**工作**

- 实现单词轻点与短语范围调整。
- 建立 LearningUnit、ExpressionConcept、Encounter 数据流。
- 实现八层 Exploration workspace。
- 保存猜测、修订、展开事件和草稿。
- 实现 Core Concept 与 Related Context 呈现。
- 实现至少两类迁移练习。
- 返回 Reader 并恢复原句位置。

**验收**

- 第一屏不出现答案性中文。
- 层级无法被错误顺序自动展开。
- 用户可以中途离开并恢复。
- 当前语境、核心概念和相关语境在 UI 与数据中独立。
- 对短语 reflect on 不会只讲解 reflect 的另一结构。
- 返回原文后定位正确，并可记录 clearer/unsure。

### Milestone 4 — Journal、复习与数据所有权

**目标**

让一次学习成为可回顾、可迁移、可备份的长期记录。

**工作**

- Journal 按文章/时间组织学习历史。
- Expression history 展示多个 Encounter。
- 计算三维 LearningSummary 和五级证据状态。
- 实现透明规则型 ReviewSchedule。
- 实现 JSON 导出与替换恢复。
- 设置页显示存储、备份与 iPhone 安装说明。

**验收**

- 同一表达的不同语境不会互相覆盖。
- 查看答案不会自动标为等级 4。
- 延迟迁移结果会更新摘要和复习时间。
- 导出后可在空测试库完整恢复。
- 损坏、不兼容或超限文件不会修改现有数据。
- 删除下载文章不删除历史 Encounter 快照。

### Milestone 5 — MVP 内容扩充与发布硬化

**目标**

从“技术演示”变成可以持续个人使用的首版。

**工作**

- 扩充到 3–5 篇不同主题/文体的策划文章。
- 审核全部核心概念、连接说明和迁移练习。
- 完成视觉细节、空状态、离线状态和错误恢复。
- 做移动性能、可访问性与数据迁移测试。
- 在 iPhone Safari 与主屏幕模式完成端到端测试。
- 建立发布检查表和备份兼容性测试样本。

**发布验收**

- 一名目标用户无需讲解可完成主学习流程。
- 全部文章具有明确来源和许可。
- 主要流程在离线、刷新和应用更新后保持数据一致。
- 没有客户端密钥、追踪 SDK、登录或远程用户数据。
- 导出文件可恢复且文档化。
- 已知限制在设置/帮助中清楚说明。

## 4. 内容工作流

内容质量是产品核心，不应等页面开发结束后再补。

### 黄金样本顺序

1. 选择一篇长度适中、主题符合兴趣的合法文章。
2. 找出 5–8 个能展示语境变化的表达，不追求数量。
3. 为每个表达完成 LearningUnit 内容。
4. 由第二轮审核检查英文自然度、中文脚手架和概念边界。
5. 在低保真原型中测试提示层级。
6. 根据用户的真实理解路径修订内容，再固化格式。

### 内容完成定义

- 来源与许可可追踪。
- 当前语境解释不依赖孤立中文译词。
- 核心概念能连接至少两个差异真实的语境。
- 连接说明明确，没有“自行领悟”的断层。
- 迁移练习不是原句表面替换。
- 英文解释的难度低于目标表达。

## 5. 测试策略

### 单元测试

- 文章 tokenization 和 TextAnchor。
- 学习摘要计算。
- 复习调度规则。
- 导入 schema 校验。
- 内容版本迁移。

### 组件测试

- 渐进层级默认折叠与顺序。
- 猜测保存与草稿恢复。
- 阅读位置恢复。
- 键盘焦点返回。
- 离线/错误/空状态。

### 端到端测试

- 首次使用到完成文章。
- 探索表达并返回原文。
- 刷新后恢复未完成探索。
- 离线打开下载文章。
- 导出、清空测试库、恢复。
- Service Worker 更新后的内容与记录关联。

### 真机测试

- iPhone Safari 浏览器。
- iPhone 添加到主屏幕后的 standalone 模式。
- 至少一种 Android Chrome 设备或仿真。
- 小屏、动态字号、横竖屏切换。

## 6. 决策门

### 开发前必须确认

- 用户批准 Phase 0 文档。
- 首篇黄金样本的来源和主题。
- MVP 对未预策划表达的处理边界。
- 导入首版是否仅支持替换恢复。
- 首版路由策略与 GitHub Pages 仓库路径。

### Milestone 3 前必须确认

- 核心概念内容模板通过真实样本验证。
- 单词轻点与短语扩展的原型可用。
- 八层流程在手机上没有明显操作疲劳。

### 发布前必须确认

- 文章许可与归属完整。
- iOS 离线和恢复测试完成。
- schemaVersion 1 备份样本纳入回归测试。

## 7. 主要风险的先行实验

| 实验 | 要回答的问题 | 最小产物 |
| --- | --- | --- |
| 提示层级纸面/低保真测试 | 八层是否过重？哪些层可以视觉合并但仍保持顺序？ | 一个表达的可点击原型 |
| 短语选择 spike | 手机轻点如何在单词与搭配间调整？ | 一段可交互文本 |
| 恢复位置 spike | 字号、视口变化后是否仍准确返回句子？ | block + TextAnchor 原型 |
| iOS PWA spike | 离线、更新、standalone 返回行为是否可靠？ | 最小部署站点 |
| 备份恢复演练 | IndexedDB 数据能否跨版本安全恢复？ | v1 fixture 与自动测试 |
| 核心概念内容评审 | 模型是否帮助迁移而非制造模糊解释？ | 5 个黄金表达内容包 |

## 8. MVP 之后

只有在 MVP 学习闭环得到验证后再考虑：

- 用户导入文章与本地内容策划。
- 更成熟的间隔调度。
- 核心概念可视化语义网络。
- 音频朗读与听读结合。
- 在不暴露密钥、不上传私人记录前提下的可选本地智能能力。
- 加密的用户主动同步方案。

这些方向不应提前改变 MVP 的架构重点：文章、语境、核心概念、迁移和重读。
